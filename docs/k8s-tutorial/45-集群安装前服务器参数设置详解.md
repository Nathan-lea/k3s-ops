# 45 集群安装前服务器参数设置详解

> 前面 44 章都在讲"装好之后怎么用"。本章回到**安装之前**：一台裸机/虚拟机，在跑 `k3s` 之前，
> 操作系统层面必须先配好哪些参数？每个参数**叫什么、设什么值、干什么用、写在哪里、设错会怎样**。
>
> 目标是把"装前准备"从"抄一段命令"变成"知道为什么要抄"。文末附一个**完整的一键设置 / 体检脚本**，
> 幂等、可重复执行，并在本集群真实跑过。

## 本章目标

读完本章你能：

- 分清装前参数里的 **"硬性"**（不设 k3s 装不上或必出问题）与 **"建议"**（不设能跑、但迟早埋雷）；
- 说出每个参数的四要素：**参数名 / 推荐值 / 作用 / 设置位置（文件路径）**；
- 理解几个最关键的原理：为什么必须关 swap、`br_netfilter` 与 `bridge-nf-call-*` 是什么关系、
  `ip_forward` 与跨节点流量、`conntrack` 表满会怎样、为什么 inotify 是 kubelet 的"隐形大户"；
- 知道**本项目的 `k3s-common` 角色自动做了其中哪些**、写到了哪个文件、还有哪些没做（需要脚本补位）；
- 用本章的一键脚本对**任意新节点**做装前初始化 + 体检（`--check` 只读模式）；
- 看懂 `nodes.yml → Ansible → /etc/rancher/k3s/config.yaml` 这条链上"安装期参数"与本章"OS 参数"的分工。

> **命令执行位置约定**：本章命令除特别说明外都**在节点上执行**。登录节点用 `./k3s-ops.sh ssh <节点名>`
> （见 `docs/ssh-login.md`），或在项目根目录用 `vagrant ssh <完整主机名> -c '<命令>'`；需要 root 的地方已标 `sudo`。

## 1. 先分清两类参数：硬性与建议

装前参数按"不设会怎样"分两类，这个划分贯穿全章，也直接决定了脚本的判定与退出码：

| 类别 | 含义 | 不设的后果 | 脚本标记 |
|------|------|-----------|---------|
| **硬性** | kubelet / CNI 启动或工作**必需** | k3s 装不上、节点 NotReady、跨节点网络不通、NetworkPolicy 失效 | `[硬性]`，不合格计入退出码 |
| **建议** | 默认值能跑，但**有规模的集群必踩** | 高负载下丢连接、kubelet 日志刷 `too many open files`、etcd 选主抖动 | `[建议]`，只提示不影响退出码 |

一句话记忆：**硬性不设"装不上/跑不通"，建议不设"平时没事、出事难查"。**

### 1.1 总览：一张表看懂"装前都设什么"

| # | 类别 | 关键内容 | 本项目由谁设置 | 级别 |
|---|------|---------|---------------|------|
| 1 | 主机名 | `/etc/hostname`、`hostnamectl` | `k3s-common` 角色（Ansible `hostname` 模块） | 建议 |
| 2 | 节点解析 | `/etc/hosts` | 手工 / 本章脚本 | 建议 |
| 3 | swap | 关掉它 + 改 `/etc/fstab` 持久化 | `k3s-common`（`swapoff -a` + 删 fstab 行） | **硬性** |
| 4 | 内核模块 | `overlay`、`br_netfilter`（本章脚本另加 `nf_conntrack`） | `k3s-common`（`/etc/modules-load.d/k3s.conf`） | **硬性** |
| 5 | sysctl | `ip_forward`、`bridge-nf-call-*`、conntrack、inotify 等 | `k3s-common` 设 3 个核心键（写入 `/etc/sysctl.conf`） | **硬性 + 建议** |
| 6 | limits | `nofile` / `nproc` | **未做**（本章脚本补位 `/etc/security/limits.d/`） | 建议 |
| 7 | 时间同步 | NTP（etcd 时钟敏感） | **未做**（依赖 box 默认 `systemd-timesyncd`） | 建议 |
| 8 | 防火墙 | ufw/firewalld 放行 k3s 端口 | `k3s-common`（`ufw` 规则，仅 6443/10250/8472/2379/2380） | **硬性**（仅当启用防火墙） |
| 9 | 依赖工具包 | `conntrack`/`jq`/`ethtool`/`socat` 等 | `k3s-common` `vars` 里**只罗列未安装** | 建议 |

> ⚠️ 注意第 6、7 项：项目 Ansible 角色**没有**管 limits 和时间同步。小集群平时无感，
> 但生产节点这两项是标配 —— 本章的一键脚本正好把这块补齐。

## 2. 主机名与 `/etc/hosts`（节点身份）

k3s 会用**主机名**注册 Node 对象，`node-name` 默认取主机名（本项目在 `config.yaml` 里显式指定，
见 §10）。主机名不规范会导致 `kubectl get nodes` 里名字混乱、证书 SAN 对不上。

| 参数 | 推荐值 | 作用 | 设置位置 | 生效方式 |
|------|-------|------|---------|---------|
| 主机名 | `<集群>-<角色>-<序号>`，如 `k3s-demo-server-1` | 节点身份、Node 名 | `hostnamectl set-hostname`（写 `/etc/hostname`） | 立即 + 重启保持 |
| 静态解析 | `<节点IP> <主机名>` | 让节点名能解析到本机 IP | `/etc/hosts` | 立即 |

本项目用 Vagrant 定义主机名：`Vagrantfile` 里 `vm.vm.hostname = "#{cluster_name}-#{node['name']}"`，
即 `k3s-demo-server-1` / `k3s-demo-agent-1`。在节点上实测：

```bash
$ hostnamectl | grep -E 'Static hostname|Operating System|Kernel'
 Static hostname: k3s-demo-server-1
Operating System: Ubuntu 22.04.5 LTS
          Kernel: Linux 5.15.0-160-generic
$ grep -E '192.168.56|127.0.1.1' /etc/hosts
127.0.1.1 vagrant
```

⚠️ **一个真实的小瑕疵**：`/etc/hosts` 里还留着 Vagrant box 的默认行 `127.0.1.1 vagrant`，
与当前主机名不符。它**不影响 k3s**（k3s 用 `config.yaml` 的 `node-name`/`node-ip` 显式指定，不靠 hosts 反查），
但生产节点建议写成规范的 `192.168.56.10 k3s-demo-server-1`。

## 3. 关闭 swap（硬性）

**这是 k8s 的硬性要求**：kubelet 默认 `--fail-swap-on=true`，只要检测到 swap **开启就直接拒绝启动**，
k3s 起不来、节点永远是 NotReady。原因是调度器按"内存可用量"分配 Pod，
swap 会让实际内存行为与调度假设不一致，导致性能抖动、OOM 判断失真。

关闭要**两条腿走路**，缺一不可：

| 动作 | 命令 | 作用 | 位置 |
|------|------|------|------|
| 立即生效 | `swapoff -a` | 关掉当前所有 swap | 内存（临时） |
| 持久化 | 注释/删除 `/etc/fstab` 里的 swap 行 | 重启后不再挂载 | `/etc/fstab` |

本项目 `k3s-common` 角色正是这么做的（`command: swapoff -a` + `mount state=absent`）。
在节点上实测：

```bash
$ swapon --show          # 空输出 = 无活动 swap
$ grep -n swap /etc/fstab
(fstab 无 swap 行)
```

> 既然 kubelet 有 `failSwapOn=false` 可以"豁免"，为什么不建议？—— 放开后 swap 会拖慢 kubelet/容器运行时，
> 且调度器算不准内存压力，属于"能跑但迟早出事"。除非有特殊需求（如 NodeSwap 特性），否则**一律关掉**。

## 4. 内核模块（硬性）

k8s 的网络与存储依赖几个内核模块，必须在**加载**层面就位，且**重启后自动加载**。

| 模块 | 必需性 | 作用 | 缺了会怎样 |
|------|-------|------|-----------|
| `overlay` | **硬性** | containerd 的 overlayfs 联合存储驱动（容器镜像分层） | containerd 启动/拉镜像失败 |
| `br_netfilter` | **硬性** | 让**网桥**上的流量也进 netfilter（否则下面的 `bridge-nf-call-*` 键根本不存在） | 桥接流量绕过 iptables，NetworkPolicy/Service 规则失效 |
| `nf_conntrack` | 建议（脚本加载） | 连接跟踪，`net.netfilter.nf_conntrack_max` 的前置 | 无法调 conntrack 表上限 |
| `ip_vs` 系列 | 按需 | 仅 kube-proxy **IPVS 模式**需要；k3s 默认 **iptables 模式**，无需 | （iptables 模式下不涉及） |

加载方式（两处配合）：

```bash
# 1) 立即加载
$ modprobe overlay && modprobe br_netfilter
# 2) 重启后自动加载：写入 /etc/modules-load.d/k3s.conf
$ cat /etc/modules-load.d/k3s.conf
overlay
br_netfilter
```

在节点上实测（k3s 运行中，`nf_conntrack` 被自动拉起的从属模块）：

```bash
$ lsmod | grep -E '^(br_netfilter|overlay|nf_conntrack) '
nf_conntrack          172032  4 xt_conntrack,nf_nat,xt_nat,xt_MASQUERADE
br_netfilter           32768  0
overlay               151552  34
```

> 注意 `/etc/modules-load.d/` 下是"开机加载"清单，`lsmod` 是"当前已加载"状态，两者要**都对**。
> 旧发行版还有 `/etc/modules` 文件（本项目 box 里也有 `modules.conf`），含义相同。

## 5. sysctl 内核参数（本章重头）

sysctl 是"装前设置"里最密集的一块。下面按**硬性 / 建议**分组逐个讲透。

### 5.1 硬性：转发与桥接

| 参数 | 推荐值 | 作用与原理 | 不设/设错的后果 |
|------|-------|-----------|----------------|
| `net.ipv4.ip_forward` | `1` | 打开 IPv4 转发。Pod 跨节点通信、Service DNAT 后的回程包，本质都要经过**本机路由/转发** | 跨节点 Pod / Service 不通（同节点也可能异常） |
| `net.bridge.bridge-nf-call-iptables` | `1` | 让**经过网桥**的帧（CNI 网桥 `cni0` / flannel `flannel.1`）也走 iptables/netfilter | kube-proxy 规则对 Pod 流量不生效，**NetworkPolicy 形同虚设** |
| `net.bridge.bridge-nf-call-ip6tables` | `1` | 同上，IPv6 侧 | IPv6/双栈集群异常 |

> 前置依赖：`br_netfilter` 模块必须先加载，否则后两个键在 `/proc/sys/net/bridge/` 下**根本不出现**，
> `sysctl` 会报 `cannot stat ...: No such file or directory`。**先模块、后 sysctl** 的顺序不能反。

### 5.2 建议：连接跟踪、队列、句柄、内存

| 参数 | 推荐值 | 作用与原理 | 不设/设错的后果 | 本项目实测 |
|------|-------|-----------|----------------|-----------|
| `net.netfilter.nf_conntrack_max` | `262144`（默认 `131072`） | 连接跟踪表上限。kube-proxy 的 Service DNAT/NodePort、NAT 全靠 conntrack 记账 | 表满 → **新连接被丢**，`dmesg` 刷 `nf_conntrack: table full, dropping packet` | `131072 → 262144` |
| `net.netfilter.nf_conntrack_tcp_timeout_established` | `86400`（默认 `432000`＝5 天） | 已建立连接的跟踪存活时间 | 长连接（如 gRPC/消息队列）长期占表，加剧表满 | 默认 `432000`（脚本未改，高连接周转场景可调） |
| `net.core.somaxconn` | `4096` | 监听队列（accept backlog）上限 | 高并发下握手被丢弃（老内核默认 128 时尤甚） | `4096` |
| `net.ipv4.ip_local_port_range` | `32768 60999` | 出站连接的临时端口范围 | **若范围包含 `30000-32767`**，会与 NodePort 抢端口 → `bind: address already in use`、NodePort 随机失效 | `32768 60999` |
| `fs.inotify.max_user_watches` | `524288`（默认 `29613`） | inotify 监控点上限。**kubelet 要为每个 Pod 的日志、`configmap`、`secret`、manifest 建立 watch** | 不足 → kubelet 报 `too many open files` / inotify 限制，Pod 状态刷新变慢甚至卡死 | `29613 → 524288` |
| `fs.inotify.max_user_instances` | `8192`（默认 `128`） | inotify 实例数上限（每个进程/容器各占） | 大量容器各自 inotify 时提前耗尽 | `128 → 8192` |
| `vm.overcommit_memory` | `1` | 允许内存超额分配（内核不因"看起来会超"而拒绝 `malloc`） | 大内存 Pod / JVM 申请内存失败；K8s 官方节点调优文档推荐置 `1` | `1` |
| `kernel.panic` | `10` | 内核 panic 后 **10 秒自动重启**（配合高可用/看门狗） | 节点 panic 后僵死，需人工重启 | `10` |
| `net.ipv4.conf.all.rp_filter` | `2`（loose） | 反向路径过滤强度（`0` 关 / `1` 严 / `2` 松） | 多网卡 + VXLAN 节点上 `1`（严格）可能丢合法包 | `2`（Ubuntu 默认，**保持不动**） |
| `fs.file-max` | 视发行版 | 全系统文件句柄上限 | —— | Ubuntu 默认 `9223372036854775807`（≈无上限，**不要调小**）；RHEL/CentOS 默认约 7.9 万，建议调至 `1048576+` |

> 💡 `ip_local_port_range` 那条坑值得展开：NodePort 服务会占用 `30000-32767`。
> 如果为了"扩大端口池"把它改成 `1024 65535`，出站连接就会随机占用 NodePort 段里的端口，
> 于是 `kube-proxy` 申请 NodePort 时报 `address already in use`，或 Service 时通时不通。
> **本项目重度使用 NodePort（ingress 的 30080/30444/30025/30443），所以刻意保持默认 `32768 60999`。**

### 5.3 生效方式与加载优先级

| 层面 | 位置 | 说明 |
|------|------|------|
| 运行中改 | `sysctl -w key=val` | 立即生效，重启丢失 |
| 持久化（推荐） | `/etc/sysctl.d/99-k3s.conf` | 开机由 `systemd-sysctl` 逐个 `.conf` 应用 |
| 项目既有 | `/etc/sysctl.conf`（`k3s-common` 的 Ansible `sysctl` 模块默认写入此文件） | `/etc/sysctl.d/99-sysctl.conf` 是它的软链 |
| 立即重载 | `sysctl --system` | 按序重放所有配置文件 |

**优先级**：`/etc/sysctl.d/*.conf` 按**文件名字典序**加载，**同名键后加载的覆盖先加载的**。
`99-k3s.conf`（k）排在 `99-sysctl.conf`（s）之前，所以 Ansible 写在 `/etc/sysctl.conf` 的同名键**最终生效**；
本项目两处取值一致，不冲突：

```bash
$ ls /etc/sysctl.d/
10-console-messages.conf  ...  99-k3s.conf  99-sysctl.conf  README.sysctl
```

> 排查时永远以**运行值**为准：`sysctl net.ipv4.ip_forward`（不是看文件里写了什么）。

## 6. 文件描述符与进程数（limits）

limits 是"登录会话级"的资源上限。kubelet、ingress、containerd 在高负载下都要开大量文件句柄，
默认 `nofile=1024` 往往不够。

| 参数 | 推荐值 | 作用 | 设置位置 |
|------|-------|------|---------|
| `nofile`（soft/hard） | `1048576` | 单进程可打开文件数上限 | `/etc/security/limits.d/99-k3s.conf` |
| `nproc`（soft/hard） | `65536` | 单用户可创建进程/线程数上限 | 同上 |

```bash
$ cat /etc/security/limits.d/99-k3s.conf
* soft nofile 1048576
* hard nofile 1048576
* soft nproc 65536
* hard nproc 65536
```

⚠️ **两个常被忽略的点**：

1. **只对"登录会话"生效**。limits 由 PAM 在登录时应用（需 `pam_limits.so`，sshd 需 `UsePAM yes`）。
   **systemd 管理的服务不看这里**——k3s.service 的句柄上限由它自己的 unit（`LimitNOFILE=`）决定。
   所以"我改了 limits 但 k3s 还是报 too many open files"很常见，要分清对象。
2. **CentOS/RHEL 有坑**：系统自带 `/etc/security/limits.d/20-nproc.conf` 会用更小的 `nproc` 覆盖你的设置，
   且**按文件名字典序后者胜**，务必让自定义文件名排在其后（如 `99-k3s.conf`）。

实测：写入后**新开一个登录会话**才生效（当前会话仍是旧值）：

```bash
$ sudo bash -lc 'ulimit -n; ulimit -u'
1048576
65536
```

## 7. 时间同步（etcd 的命门）

k3s 默认用**嵌入式 etcd** 存集群状态。etcd 的 Raft 协议用**墙上时钟**做租约（lease）与选主判断，
**时钟漂移过大会导致选主抖动、租约误判、日志报 `clock skew`**，严重时集群不可写。

| 参数 | 推荐值 | 作用 | 设置位置 |
|------|-------|------|---------|
| NTP 服务 | 持续同步（偏差毫秒级） | 保证各节点时钟一致 | systemd：`/etc/systemd/timesyncd.conf` 的 `NTP=`；或 `chrony`：`/etc/chrony/chrony.conf` |
| 检查 | `NTPSynchronized=yes` | 判断是否已同步 | `timedatectl show -p NTPSynchronized` |

```bash
$ timedatectl show -p NTPSynchronized
NTPSynchronized=yes
```

> **本集群实况**：实验室环境公网 NTP 经常不可达，早期检查时是 `NTPSynchronized=no`、`Packet count: 0`，
> 后来由 box 的 `systemd-timesyncd` 同步成功。演示环境可以接受，**生产必须配内网 NTP 服务器**：
> `NTP=ntp.internal` 写入 `timesyncd.conf`，或改用 `chrony` 指明内网源。

## 8. 防火墙与端口（硬性）

如果节点启用了主机防火墙（`ufw` / `firewalld`），必须放行 k3s 端口，否则节点间握手失败、
kubelet 上报异常。k3s 端口清单（官方要求）：

| 节点角色 | 端口 | 协议 | 用途 |
|---------|------|------|------|
| **server** | `6443` | TCP | Kubernetes API（kubectl/agent 连它） |
| **server** | `2379` | TCP | 嵌入式 etcd 客户端（apiserver 连它） |
| **server** | `2380` | TCP | 嵌入式 etcd peer（server 之间选举/复制） |
| **server** | `10250` | TCP | kubelet API（apiserver 拉指标、exec、logs） |
| **server** | `10257` | TCP | kube-controller-manager（metrics） |
| **server** | `10259` | TCP | kube-scheduler（metrics） |
| **全节点** | `8472` | UDP | flannel **VXLAN** 跨节点 Pod 网络 |
| **全节点** | `51820` / `51821` | UDP | flannel **WireGuard** 后端（本项目用 vxlan，不涉及） |
| **全节点** | `30000-32767` | TCP | NodePort 段（本项目 ingress 用 30080/30444/30025/30443） |

放行命令：

```bash
# Ubuntu（ufw）——本项目 k3s-common 角色就是这么做的
$ sudo ufw allow 6443/tcp && sudo ufw allow 2379/tcp && sudo ufw allow 2380/tcp
$ sudo ufw allow 10250/tcp && sudo ufw allow 8472/udp

# RHEL/CentOS（firewalld）
$ sudo firewall-cmd --permanent --add-port=6443/tcp --add-port=2379-2380/tcp \
     --add-port=10250/tcp --add-port=8472/udp
$ sudo firewall-cmd --reload
```

本项目实测（**防火墙未启用，端口天然全通**）：

```bash
$ sudo ufw status | head -1
Status: inactive
$ iptables --version
iptables v1.8.7 (nf_tables)
```

> ⚠️ **iptables 后端一致性**：`iptables` 有 `legacy` 与 `nftables` 两套后端（`iptables-nft`/`iptables-legacy`），
> 两者规则**互不可见**。k3s 会自带并使用一套 iptables 二进制；如果宿主机上混用（一半工具走 legacy、
> 一半走 nftables），排查时会看到"规则明明加了却不生效"。**Ubuntu 22.04 默认 `nf_tables`（见上），保持统一即可，切勿中途切换。**

## 9. 依赖工具包（建议）

k3s 是**单二进制**，自带 containerd / kubelet / kubectl / ctr / iptables，**不严格依赖**系统软件包。
但排障常用工具值得装齐：

| 工具 | 用途 |
|------|------|
| `conntrack` | 查看/清理连接跟踪表（conntrack 表满时救命） |
| `jq` | 解析 `kubectl -o json` 输出 |
| `ethtool` | 查看网卡、VXLAN 接口状态 |
| `socat` / `ipset` / `iptables` / `curl` / `wget` | 网络排查、端口连通性 |

本项目 `k3s-common` 的 `vars/main.yml` **只列出了清单但没有安装任务**（`packages:` 变量无人引用）。
节点实测，缺 4 个：

```bash
$ for p in conntrack jq ethtool socat ipset; do command -v $p || echo "缺: $p"; done
缺: conntrack
缺: jq
缺: socat
缺: ipset
```

> 本环境软件源不可达（`apt` 装不上），脚本会**优雅降级**：报 `[建议] 仍缺少...，请手动安装`，不阻断流程。
> 生产环境按 §12 的 `--skip-packages` 开关决定是否安装。

## 10. 与 k3s 安装期参数（`config.yaml`）的分工

本章讲的是 **OS 层参数**。"装前"还有一个层次是 **k3s 自身的启动参数**，由
`nodes.yml → Ansible → /etc/rancher/k3s/config.yaml` 下发。两者的分工：

| 层次 | 例子 | 谁来设 | 生效时机 |
|------|------|-------|---------|
| OS 层（本章） | swap、模块、sysctl、limits、NTP、防火墙 | `k3s-common` / 本章脚本 | k3s 启动**之前**就要满足 |
| k3s 层（§10） | `cluster-init`、`disable`、`flannel-iface`、`node-ip` | Ansible 模板 → `config.yaml` | k3s 启动时读取 |

本项目节点上真实的 `/etc/rancher/k3s/config.yaml`：

```yaml
# server 节点（节选，Ansible managed）
node-name: k3s-demo-server-1
node-ip: 192.168.56.10
advertise-address: 192.168.56.10
cluster-cidr: 10.42.0.0/16
service-cidr: 10.43.0.0/16
disable:
  - traefik
  - servicelb
flannel-backend: vxlan
flannel-iface: eth1
kubelet-arg:
  - "allowed-unsafe-sysctls=net.ipv4.ip_forward"
etcd-expose-metrics: true
node-taint: []
cluster-init: true
```

```yaml
# agent 节点
server: https://192.168.56.10:6443
token: <REDACTED>
node-name: k3s-demo-agent-1
node-ip: 192.168.56.20
flannel-iface: eth1
```

> 两点呼应本章：
> ① `flannel-iface: eth1` 显式指定用 host-only 网卡做 VXLAN —— 所以 §5 的 `ip_forward`、
> `br_netfilter` 必须就位，跨节点 Pod 网络才通；
> ② `kubelet-arg: allowed-unsafe-sysctls=net.ipv4.ip_forward` 是"允许 **Pod** 设置这个 unsafe sysctl"，
> 与本章"**节点**层面开启 `ip_forward`"是两码事，别混淆。

## 12. 一键设置 / 体检脚本

### 12.1 设计要点

- **幂等**：可重复执行；已正确的项直接跳过，不会反复改文件。
- **两种模式**：默认"应用并校验"；`--check` 只读体检，**退出码 = 硬性不合格项数**（可用于 CI/巡检）。
- **分级**：`[硬性]` 计入退出码；`[建议]` 只提示。
- **自动识别**：防火墙自动区分 `ufw` / `firewalld` / 未启用；包管理自动区分 `apt` / `dnf`。
- **优雅降级**：软件源不可达、NTP 上游不通时给 `[建议]` 警告，不中断。

保存到项目 `tmp/` 目录（`tmp/` 不进版本库，符合项目约定）：

```bash
$ mkdir -p ~/k3s-ops/tmp
$ vi ~/k3s-ops/tmp/node-preconfig.sh    # 粘贴下面全文
$ chmod +x ~/k3s-ops/tmp/node-preconfig.sh
```

### 12.2 脚本全文

```bash
#!/usr/bin/env bash
#===============================================================================
# k3s 安装前服务器参数一键设置 / 体检脚本（对应教程第 45 章）
#
# 覆盖项：主机名、/etc/hosts、swap、内核模块、sysctl、limits、
#         时间同步、依赖工具包、防火墙端口（ufw / firewalld 自动识别）
# 特性：幂等（可重复执行）、--check 只体检不改动、
#       区分"硬性"（不通过则 k3s 装不上/必出问题）与"建议"（埋雷项）
#
# 用法：
#   sudo ./node-preconfig.sh                       # 应用全部默认设置
#   sudo ./node-preconfig.sh --check               # 只体检；退出码 = 硬性不合格项数
#   sudo ./node-preconfig.sh --role server         # server 节点（多开 API/etcd 端口）
#   sudo ./node-preconfig.sh --hostname k3s-demo-agent-2 \
#        --hosts-entry "192.168.56.21 k3s-demo-agent-2"
#   sudo ./node-preconfig.sh --nodeports           # 额外放行 NodePort 段 30000-32767
#   sudo ./node-preconfig.sh --skip-packages       # 不安装依赖工具包
#===============================================================================
set -euo pipefail

# ------------------------------- 参数解析 -------------------------------------
ROLE="agent"
HOSTNAME_ARG=""
HOSTS_ENTRY=""
CHECK_ONLY=0
SKIP_PACKAGES=0
NODEPORTS=0

while [[ $# -gt 0 ]]; do
  case "$1" in
    --check)         CHECK_ONLY=1; shift ;;
    --role)          ROLE="${2:?--role 需要 server|agent}"; shift 2 ;;
    --hostname)      HOSTNAME_ARG="${2:?--hostname 需要名称}"; shift 2 ;;
    --hosts-entry)   HOSTS_ENTRY="${2:?--hosts-entry 需要 \"IP 名称\"}"; shift 2 ;;
    --nodeports)     NODEPORTS=1; shift ;;
    --skip-packages) SKIP_PACKAGES=1; shift ;;
    -h|--help)       sed -n '2,17p' "$0" | sed 's/^# \{0,1\}//'; exit 0 ;;
    *) echo "未知参数: $1（-h 查看用法）"; exit 2 ;;
  esac
done
case "$ROLE" in server|agent) ;; *) echo "--role 只能是 server 或 agent"; exit 2 ;; esac
if [[ $EUID -ne 0 ]]; then echo "请用 root 执行：sudo $0 ..."; exit 1; fi

# ------------------------------- 输出工具 -------------------------------------
if [[ -t 1 ]]; then
  C_G=$'\033[32m'; C_R=$'\033[31m'; C_Y=$'\033[33m'; C_B=$'\033[1m'; C_0=$'\033[0m'
else
  C_G=""; C_R=""; C_Y=""; C_B=""; C_0=""
fi
N_PASS=0; N_WARN=0; N_FAIL=0
ok()   { echo "  ${C_G}[通过]${C_0} $*"; N_PASS=$((N_PASS+1)); }
warn() { echo "  ${C_Y}[建议]${C_0} $*"; N_WARN=$((N_WARN+1)); }
fail() { echo "  ${C_R}[硬性]${C_0} $*"; N_FAIL=$((N_FAIL+1)); }
note() { echo "  ${C_B}[信息]${C_0} $*"; }
step() { echo; echo "${C_B}== $* ==${C_0}"; }

SYSCTL_FILE=/etc/sysctl.d/99-k3s.conf
LIMITS_FILE=/etc/security/limits.d/99-k3s.conf
MODULES_FILE=/etc/modules-load.d/k3s.conf
MARK="# 由 k3s-ops node-preconfig.sh 管理（第 45 章），请勿手改后又执行脚本覆盖"

# ------------------------------- 1. 主机名 ------------------------------------
do_hostname() {
  step "1/9 主机名"
  local cur; cur=$(hostname)
  if [[ -z "$HOSTNAME_ARG" ]]; then
    note "未指定 --hostname，保持当前主机名: $cur"
    return
  fi
  if [[ "$cur" == "$HOSTNAME_ARG" ]]; then
    ok "主机名已是 $cur"
    return
  fi
  if [[ $CHECK_ONLY -eq 1 ]]; then
    fail "主机名 $cur ≠ 目标 $HOSTNAME_ARG"
    return
  fi
  hostnamectl set-hostname "$HOSTNAME_ARG"
  ok "主机名已设置为 $HOSTNAME_ARG"
}

# ------------------------------- 2. /etc/hosts --------------------------------
do_hosts() {
  step "2/9 /etc/hosts 节点名解析"
  if [[ -n "$HOSTS_ENTRY" ]]; then
    local name; name=${HOSTS_ENTRY##* }
    if grep -qE "^[^#]*\b${name}\b" /etc/hosts; then
      ok "/etc/hosts 已包含 $name 的映射"
    elif [[ $CHECK_ONLY -eq 1 ]]; then
      fail "/etc/hosts 缺少条目: $HOSTS_ENTRY"
    else
      echo "$HOSTS_ENTRY" >> /etc/hosts
      ok "已追加 /etc/hosts 条目: $HOSTS_ENTRY"
    fi
  else
    note "未指定 --hosts-entry，跳过写入"
  fi
  # 提示 box 默认残留（不自动改，避免破坏 vagrant 网络假设）
  local stale; stale=$(grep -E '^127\.0\.1\.1' /etc/hosts | awk '{print $2}' || true)
  if [[ -n "$stale" && "$stale" != "$(hostname)" ]]; then
    warn "/etc/hosts 残留 '127.0.1.1 $stale'（box 默认值，与当前主机名不符；无碍 k3s，介意可手动改）"
  fi
}

# ------------------------------- 3. swap --------------------------------------
do_swap() {
  step "3/9 关闭 swap"
  local active; active=$(swapon --show 2>/dev/null | grep -c . || true)
  local fstab_swap; fstab_swap=$(grep -Ec '^[^#].*[[:space:]]swap[[:space:]]' /etc/fstab || true)
  if [[ "$active" == 0 && "$fstab_swap" == 0 ]]; then
    ok "swap 已关闭且 fstab 无 swap 项"
    return
  fi
  if [[ $CHECK_ONLY -eq 1 ]]; then
    [[ "$active" != 0 ]] && fail "有 $active 个活动 swap（kubelet 默认 failSwapOn=true 会拒启）"
    [[ "$fstab_swap" != 0 ]] && fail "fstab 有 $fstab_swap 行未注释 swap（重启后 swap 会复活）"
    return
  fi
  if [[ "$active" != 0 ]]; then
    swapoff -a && ok "swapoff -a 已关闭全部 swap"
  fi
  if [[ "$fstab_swap" != 0 ]]; then
    sed -ri "s|^([^#].*[[:space:]]swap[[:space:]])|# k3s-preconfig-已禁用swap: \1|" /etc/fstab
    ok "fstab 中 swap 行已注释（重启后不再挂载）"
  fi
}

# ------------------------------- 4. 内核模块 ----------------------------------
do_modules() {
  step "4/9 内核模块"
  local mods=(overlay br_netfilter nf_conntrack)
  local m missing=() need_file=0
  for m in "${mods[@]}"; do grep -q "^$m " /proc/modules 2>/dev/null || missing+=("$m"); done
  for m in "${mods[@]}"; do grep -qx "$m" "$MODULES_FILE" 2>/dev/null || need_file=1; done
  if [[ $need_file -eq 1 ]]; then
    if [[ $CHECK_ONLY -eq 1 ]]; then
      fail "$MODULES_FILE 缺失或不完整（重启后模块不会自动加载）"
    else
      printf '%s\n%s\n' "$MARK" "$(printf '%s\n' "${mods[@]}")" > "$MODULES_FILE"
      ok "已写入 $MODULES_FILE（${mods[*]}）"
    fi
  else
    ok "$MODULES_FILE 已就绪（${mods[*]}）"
  fi
  if [[ ${#missing[@]} -gt 0 ]]; then
    if [[ $CHECK_ONLY -eq 1 ]]; then
      warn "模块未加载: ${missing[*]}（modprobe 即可）"
    else
      for m in "${missing[@]}"; do modprobe "$m"; done
      ok "已 modprobe: ${missing[*]}"
    fi
  else
    ok "模块均已加载: ${mods[*]}"
  fi
}

# ------------------------------- 5. sysctl ------------------------------------
SYSCTL_CONF=$(cat <<EOF
$MARK
# ---- 硬性：转发与桥接（不设则跨节点流量/NetworkPolicy 必坏）----
net.ipv4.ip_forward = 1
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
# ---- 建议：连接跟踪表（默认 131072，中高流量节点建议翻倍）----
net.netfilter.nf_conntrack_max = 262144
# ---- 建议：监听队列 / 临时端口范围（32768-60999 刻意避开 NodePort 30000-32767）----
net.core.somaxconn = 4096
net.ipv4.ip_local_port_range = 32768 60999
# ---- 建议：inotify（kubelet 大量 watch 的大户）----
fs.inotify.max_user_watches = 524288
fs.inotify.max_user_instances = 8192
# ---- 建议：内存过量提交 & 内核 panic 后自动重启 ----
vm.overcommit_memory = 1
kernel.panic = 10
# 注意：fs.file-max 故意不设——Ubuntu 默认已是 9223372036854775807（≈无上限），
#   写 1048576 反而把上限调低；仅 RHEL/CentOS（默认约 7.9 万）需要调高时再放开：
# fs.file-max = 1048576
EOF
)
# 有序数组（顺序稳定，便于对照输出）
SYSCTL_HARD=(
  "net.ipv4.ip_forward=1"
  "net.bridge.bridge-nf-call-iptables=1"
  "net.bridge.bridge-nf-call-ip6tables=1"
)
SYSCTL_SOFT=(
  "net.netfilter.nf_conntrack_max=262144"
  "net.core.somaxconn=4096"
  "fs.inotify.max_user_watches=524288"
  "fs.inotify.max_user_instances=8192"
)

do_sysctl() {
  step "5/9 sysctl 内核参数"
  # —— 先持久化（非体检模式），再校验实际生效值
  if [[ "$CHECK_ONLY" -eq 0 ]]; then
    if [[ ! -f "$SYSCTL_FILE" ]] || ! diff -q <(echo "$SYSCTL_CONF") "$SYSCTL_FILE" >/dev/null 2>&1; then
      echo "$SYSCTL_CONF" > "$SYSCTL_FILE"
      sysctl --system >/dev/null 2>&1 || true   # 个别键不存在也不中断，随后逐项校验
      ok "已写入 $SYSCTL_FILE 并立即生效"
    else
      ok "$SYSCTL_FILE 已是最新（幂等跳过）"
    fi
  fi
  # —— 硬性项（当前值必须正确）
  local item k want got
  for item in "${SYSCTL_HARD[@]}"; do
    k=${item%%=*}; want=${item#*=}
    got=$(sysctl -n "$k" 2>/dev/null || echo MISSING)
    if [[ "$got" == "$want" ]]; then
      ok "$k = $got"
    else
      fail "$k = $got（应为 $want）"
    fi
  done
  # —— 建议项（低于推荐值只提示）
  for item in "${SYSCTL_SOFT[@]}"; do
    k=${item%%=*}; want=${item#*=}
    got=$(sysctl -n "$k" 2>/dev/null || echo MISSING)
    if [[ "$got" == "MISSING" ]]; then
      warn "$k 不存在（对应内核模块未加载？）"
    elif [[ "$got" -ge "$want" ]] 2>/dev/null; then
      ok "$k = $got"
    else
      warn "$k = $got（推荐 ≥ $want）"
    fi
  done
  # —— 文件持久化（体检模式只报告）
  if [[ "$CHECK_ONLY" -eq 1 ]]; then
    [[ -f "$SYSCTL_FILE" ]] && ok "$SYSCTL_FILE 存在" || warn "$SYSCTL_FILE 不存在（重启后建议项会回落默认值）"
  fi
}

# ------------------------------- 6. limits ------------------------------------
LIMITS_CONF=$(cat <<EOF
$MARK
# 大文件句柄（kubelet/ingress 常客）；仅对"登录会话"生效，systemd 服务看单元里的 LimitNOFILE
* soft nofile 1048576
* hard nofile 1048576
* soft nproc 65536
* hard nproc 65536
EOF
)
do_limits() {
  step "6/9 文件描述符与进程数（limits）"
  if [[ "$CHECK_ONLY" -eq 0 ]]; then
    if [[ ! -f "$LIMITS_FILE" ]] || ! diff -q <(echo "$LIMITS_CONF") "$LIMITS_FILE" >/dev/null 2>&1; then
      echo "$LIMITS_CONF" > "$LIMITS_FILE"
      ok "已写入 $LIMITS_FILE（重新登录后生效）"
    else
      ok "$LIMITS_FILE 已是最新（幂等跳过）"
    fi
  fi
  if [[ -f "$LIMITS_FILE" ]] && grep -q "1048576" "$LIMITS_FILE"; then
    ok "limits 已配置 nofile 1048576"
  else
    warn "limits 未配置（当前登录会话 nofile=$(ulimit -n)，高负载下建议 1048576）"
  fi
}

# ------------------------------- 7. 时间同步 ----------------------------------
do_time() {
  step "7/9 时间同步"
  local synced; synced=$(timedatectl show -p NTPSynchronized --value 2>/dev/null || echo unknown)
  if [[ "$synced" == "yes" ]]; then
    ok "NTP 已同步（etcd 时钟安全）"
    return
  fi
  if [[ $CHECK_ONLY -eq 1 ]]; then
    warn "NTP 未同步（etcd Raft 对时钟漂移敏感；生产必须配内网 NTP）"
    return
  fi
  timedatectl set-ntp true >/dev/null 2>&1 || true
  if [[ "$(timedatectl show -p NTPSynchronized --value 2>/dev/null)" == "yes" ]]; then
    ok "已启用并完成 NTP 同步"
  else
    warn "仍无法同步（上游 NTP 不可达？）。请配置内网 NTP：/etc/systemd/timesyncd.conf 的 NTP= 或改用 chrony"
  fi
}

# ------------------------------- 8. 依赖工具包 --------------------------------
PKGS=(conntrack jq ethtool socat ipset curl wget)
do_packages() {
  step "8/9 依赖工具包"
  if [[ "$SKIP_PACKAGES" -eq 1 ]]; then note "按 --skip-packages 跳过"; return; fi
  local p missing=() still=()
  for p in "${PKGS[@]}"; do command -v "$p" >/dev/null 2>&1 || missing+=("$p"); done
  if [[ ${#missing[@]} -gt 0 && $CHECK_ONLY -eq 0 ]]; then
    note "尝试安装缺失包: ${missing[*]}"
    if command -v apt-get >/dev/null 2>&1; then
      DEBIAN_FRONTEND=noninteractive apt-get install -y --no-install-recommends "${missing[@]}" >/dev/null 2>&1 || true
    elif command -v dnf >/dev/null 2>&1; then
      local dnfp=(); for p in "${missing[@]}"; do [[ "$p" == conntrack ]] && p=conntrack-tools; dnfp+=("$p"); done
      dnf install -y "${dnfp[@]}" >/dev/null 2>&1 || true
    else
      note "未识别 apt/dnf，跳过自动安装"
    fi
  fi
  for p in "${PKGS[@]}"; do command -v "$p" >/dev/null 2>&1 || still+=("$p"); done
  if [[ ${#still[@]} -eq 0 ]]; then
    ok "工具包齐全: ${PKGS[*]}"
  elif [[ $CHECK_ONLY -eq 1 ]]; then
    warn "缺少工具包: ${still[*]}（不阻塞安装，但排障常用）"
  else
    warn "仍缺少: ${still[*]}（网络/软件源不可达），请手动安装"
  fi
}

# ------------------------------- 9. 防火墙端口 --------------------------------
do_firewall() {
  step "9/9 防火墙端口"
  local ports=(10250/tcp 8472/udp)   # 所有节点：kubelet API、flannel VXLAN
  if [[ "$ROLE" == server ]]; then
    ports+=(6443/tcp 2379/tcp 2380/tcp 10257/tcp 10259/tcp)  # API、etcd、controller-manager、scheduler
  fi
  [[ "$NODEPORTS" -eq 1 ]] && ports+=(30000-32767/tcp)

  local fw="off" usts=""
  if systemctl is-active --quiet firewalld 2>/dev/null; then
    fw=firewalld
  elif command -v ufw >/dev/null 2>&1; then
    usts=$(ufw status 2>/dev/null || true)
    [[ "$usts" == "Status: active"* ]] && fw=ufw
  fi

  if [[ "$fw" == off ]]; then
    ok "主机防火墙未启用（ufw/firewalld 均未激活），端口天然全通"
    return
  fi
  note "识别到主机防火墙: $fw（role=$ROLE，需放行: ${ports[*]}）"

  local p num clist
  if [[ $CHECK_ONLY -eq 1 ]]; then
    for p in "${ports[@]}"; do
      num=${p%%/*}
      if [[ "$fw" == ufw ]]; then
        if grep -qE "(^|[[:space:]])${num}([/[:space:]]|$)" <<<"$usts"; then
          ok "ufw 已放行 $p"
        else
          fail "ufw 未放行 $p"
        fi
      else
        clist=$(firewall-cmd --list-ports 2>/dev/null || true)
        if grep -q "${p/\//-}" <<<"$clist"; then
          ok "firewalld 已放行 $p"
        else
          fail "firewalld 未放行 $p"
        fi
      fi
    done
    return
  fi
  for p in "${ports[@]}"; do
    if [[ "$fw" == ufw ]]; then
      ufw --force allow "$p" >/dev/null
    else
      firewall-cmd --permanent --add-port="${p/\//-}" >/dev/null
    fi
  done
  [[ "$fw" == firewalld ]] && firewall-cmd --reload >/dev/null
  ok "已按 role=$ROLE 放行: ${ports[*]}"
}

# ------------------------------- 汇总 -----------------------------------------
echo "${C_B}k3s 安装前参数体检/设置（模式: $([[ $CHECK_ONLY -eq 1 ]] && echo '只体检 --check' || echo '应用并校验')，角色: $ROLE，主机: $(hostname)）${C_0}"

do_hostname
do_hosts
do_swap
do_modules
do_sysctl
do_limits
do_time
do_packages
do_firewall

echo
echo "${C_B}==================== 结果汇总 ====================${C_0}"
printf '  通过 %d ｜ 建议 %d ｜ 硬性不合格 %d\n' "$N_PASS" "$N_WARN" "$N_FAIL"
if [[ $CHECK_ONLY -eq 1 && $N_FAIL -gt 0 ]]; then
  echo "  ${C_R}存在硬性不合格项，装 k3s 前必须修复${C_0}"
elif [[ $N_FAIL -eq 0 && $N_WARN -eq 0 ]]; then
  echo "  ${C_G}全部通过，可以安装 k3s${C_0}"
else
  echo "  ${C_G}硬性项全部通过${C_0}（建议项不影响安装，但建议处理）"
fi
exit "$N_FAIL"
```

## 动手练习

1. **读懂判定**：在某节点执行 `sudo node-preconfig.sh --check --role server; echo "退出码=$?"`，
   然后在 `/etc/sysctl.conf` 里把 `net.ipv4.ip_forward` 临时改成 `0`（`sysctl -w`），再跑一次 `--check`，
   观察它变成 `[硬性]` 计不合格、退出码变为 1；改回 `1` 后恢复。体会"硬性计入退出码"。
2. **验证 limits 生效范围**：改完 `limits.d/99-k3s.conf` 后，对比"新登录会话 `ulimit -n`"与
   "`sudo systemctl show k3s -p LimitNOFILE`"，理解登录会话与 systemd 服务的两套上限。
3. **NodePort 与端口范围**：`sysctl -w net.ipv4.ip_local_port_range="1024 65535"`，
   尝试新建一个 `NodePort` Service 并观察是否出现 `address already in use`；改回 `32768 60999` 复测。
4. **conntrack 观察**：`conntrack -C`（已装 conntrack 时）查看当前跟踪条目数，对照
   `sysctl net.netfilter.nf_conntrack_max`，理解"表和容量"的关系。

## 本章要点

- 装前参数分**硬性**（swap、`overlay`/`br_netfilter`、`ip_forward`、`bridge-nf-call-*`、防火墙端口）
  与**建议**（conntrack、inotify、limits、NTP、工具包）两类。
- **先模块、后 sysctl**：`br_netfilter` 不加载，`bridge-nf-call-*` 键根本不存在。
- `ip_local_port_range` 不要碰 `30000-32767`（NodePort 段），否则端口冲突。
- limits 只对**登录会话**生效；systemd 服务看 unit 里的 `LimitNOFILE`。
- 本项目 `k3s-common` 角色已自动配好 swap / 模块 / 三个硬性 sysctl / ufw 端口；
  **limits 与时间同步由本章脚本补位**。
- 一键脚本 `node-preconfig.sh` 幂等、`--check` 只读、退出码可用于巡检，
  并在本集群（server-1 / agent-1）真实跑通。
