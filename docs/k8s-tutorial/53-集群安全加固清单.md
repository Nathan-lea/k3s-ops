# 53 集群安全加固清单：审计、加固基线与运行时防护

## 章节信息

| 项目 | 内容 |
|------|------|
| 适用平台 | Linux / macOS（标准路径）；Windows（ops VM 路径，在 ops VM 内执行 kubectl/脚本；节点检查通过 SSH） |
| 前置章节 | 07/32/35/39/43/50/52 |
| 预计耗时 | 60-120 分钟（清单评估）；完整加固落地按环境规模需数天到数周 |
| 破坏性操作 | 低（本章默认只读检查）。若按清单实施加固，可能影响业务：启用 PSA/NetworkPolicy/Kyverno、收紧 RBAC、轮换凭据、重启 API Server 等均有风险，必须在变更窗口执行。 |
| 实测环境 | k3s v1.30.2+k3s2，双节点（server-1 192.168.56.10，agent-1 192.168.56.20），见 [00-README](00-README.md) |

## 本章目标

- 把前面分散的安全能力（RBAC、NetworkPolicy、Pod Security、Kyverno、Secret 管理、镜像供应链）汇成一份可执行清单。
- 能对现有集群做基础安全盘点：身份、网络、工作负载、准入、密钥、节点、审计、备份恢复。
- 理解“加固不是装一个工具”：要同时覆盖预防、检测、响应和恢复。
- 明确本实验集群的已知缺口和生产环境补齐方向。

> 本章不是渗透测试报告，也不是合规认证结论。任何主动测试都应在授权范围内进行；生产变更前先备份、评审、灰度。

## 2. 快速盘点命令（只读）

以下命令用于建立基线，不会修改集群状态。

```bash
export KUBECONFIG=./kubeconfig

# 身份与权限
kubectl get nodes -o wide
kubectl auth can-i --list --as=system:serviceaccount:default:default -n default
kubectl get clusterrolebinding | grep -E 'cluster-admin|system:masters'

# 工作负载与策略
kubectl get pods -A -o wide
kubectl get ns --show-labels
kubectl get networkpolicy -A
kubectl get validatingwebhookconfigurations,mutatingwebhookconfigurations
kubectl get clusterpolicy -A 2>/dev/null || echo "Kyverno CRD not installed"

# 密钥与配置
kubectl get secrets -A --no-headers | wc -l
kubectl get storageclass
kubectl get addon -A 2>/dev/null || true

# 暴露面
kubectl get svc -A | grep -E 'NodePort|LoadBalancer'
kubectl get ingress -A
kubectl get gateway,httproute -A 2>/dev/null || true
```

vagrant ssh k3s-demo-server-1 -c "sudo cat /etc/rancher/k3s/config.yaml"

vagrant ssh k3s-demo-server-1 -c "sudo ls -l /var/lib/rancher/k3s/server/manifests"

## 3. 实测盘点摘要（2026-11-26）

| 检查项 | 实测观察 | 风险判断 | 建议 |
|---|---|---|---|
| 节点状态 | server-1/agent-1 均 Ready，v1.30.2+k3s2 | 基础正常 | 持续纳入监控/告警 |
| API/etcd 监听 | `6443`、`10250` 监听 `*`；`2379/2380` 监听 `127.0.0.1` 与 `192.168.56.10` | 符合小集群常见形态；6443/10250 暴露面需靠网络边界控制 | 生产环境限制管理端口来源；避免公网暴露 |
| secrets-encryption | `/etc/rancher/k3s/config.yaml` 未见 `secrets-encryption`/`encryption-provider` | Secret 落盘未启用 K8s at-rest 加密（取决于实际配置/版本特性） | 评估启用 k3s secrets encryption；同时加强备份加密 |
| NetworkPolicy | 仅 `netpol-demo`、`policy-demo`、`cattle-fleet-local-system` 有策略 | 大多数命名空间未默认隔离 | 为业务命名空间建立 default-deny + 明确放行 |
| PSA 标签 | 多数命名空间无 `pod-security.kubernetes.io/*` 标签 | 工作负载安全基线未强制 | 先 warn/audit，再 enforce（从新命名空间开始） |
| Kyverno | 4 控制器运行中，有 webhook 配置 | 有准入能力，但 agent-1 单点 | 扩副本/多节点分布；保留逃生流程 |
| Pod securityContext | 部分系统 Pod 有合理限制，仍有空 securityContext | 不一致 | 用 Kyverno/PSA 逐步收敛；系统组件按需豁免 |
| cluster-admin 绑定 | 存在 `cluster-admin`、Rancher、system-upgrade-controller 等绑定 | 正常但需审计 | 定期审查绑定；限制人类 cluster-admin 数量 |
| 默认 SA 权限 | `default:default` 在 `default` ns 不能 get pods（实测 `no`） | 基线尚可 | 仍建议禁用 automountServiceAccountToken，按需授权 |

> 以上是实验环境快照，不是完整安全审计。生产环境应结合 CIS Benchmark、云安全基线、漏洞扫描和审计日志做正式评估。

## 4. 加固清单

### 4.1 身份与访问控制

- [ ] **最小权限 RBAC**：人用角色、程序用 ServiceAccount；避免长期 cluster-admin。
- [ ] **审查 ClusterRoleBinding**：重点关注 `cluster-admin`、`*-admin`、webhook/controller 绑定。
- [ ] **ServiceAccount 管理**：默认 SA 不授予敏感权限；不需要 API 访问的 Pod 设置 `automountServiceAccountToken: false`。
- [ ] **kubeconfig 保护**：`kubeconfig` 视为凭据；权限 600；不入 Git；定期轮换。
- [ ] **Rancher/管理 UI**：强密码/MFA（如支持）、最小角色、审计登录；NodePort 暴露面受网络策略限制。
- [ ] **Secret 访问边界**：没有 `get/list/watch secrets` 就不能读明文；但不能阻止 cluster-admin 或有 exec/创建 Pod 权限的间接读取（见第 50 章）。

### 4.2 Secret 与数据保护

- [ ] **Git 不存明文 Secret**：用 SOPS/SealedSecrets/ESO/Vault（第 50 章）。
- [ ] **启用/评估 at-rest 加密**：k3s secrets encryption；确认备份也被保护。
- [ ] **备份加密与访问控制**：etcd snapshot、PV 备份、对象存储 bucket 均需加密和 IAM 控制。
- [ ] **轮换策略**：数据库密码、token、证书、registry 凭据有过期和轮换流程。
- [ ] **审计 Secret 读取**：API audit log 记录 `secrets` get/list/watch。

### 4.3 工作负载与 Pod 安全

- [ ] **securityContext 基线**：`runAsNonRoot`、`allowPrivilegeEscalation=false`、`readOnlyRootFilesystem`（按需）、`capabilities.drop: ["ALL"]`。
- [ ] **PSA 标签**：新 namespace 先 `warn/audit`，稳定后 `enforce`。系统 namespace 按需豁免。
- [ ] **禁止高危配置**：`privileged`、`hostNetwork/hostPID/hostIPC`、敏感 hostPath、`CAP_SYS_ADMIN` 等仅在明确场景允许。
- [ ] **资源限制**：requests/limits、LimitRange、ResourceQuota 防止 noisy neighbor 和资源耗尽。
- [ ] **镜像策略**：固定 tag 或 digest；禁止未知 registry；扫描漏洞；关键业务考虑签名验签。
- [ ] **Kyverno/Gatekeeper**：把组织规则变成准入策略，策略本身要有回滚和逃生流程（第 43 章）。

### 4.4 网络与暴露面

- [ ] **默认拒绝东西向流量**：业务 namespace 使用 default-deny NetworkPolicy，再放行必要流量（第 35 章）。
- [ ] **控制南北向入口**：只暴露 Ingress/Gateway 必要端口；管理端口不对公网开放。
- [ ] **ServiceLB/NodePort 审计**：确认 30080/30444/30443 等端口用途；避免意外 NodePort。
- [ ] **TLS**：Ingress/Gateway 使用有效证书；内部敏感通信按需 mTLS/加密。
- [ ] **管理平面保护**：6443、10250、2379/2380 仅可信网络可达；etcd 不应公网暴露。

### 4.5 节点与 k3s 配置

- [ ] **最小化节点暴露**：关闭不必要服务；SSH 密钥登录；限制 sudo。
- [ ] **k3s 配置审计**：`/etc/rancher/k3s/config.yaml` 纳入版本管理/审计；`disable` 项明确。
- [ ] **内置 manifests 管控**：`/var/lib/rancher/k3s/server/manifests` 不随意手改（第 51 章）。
- [ ] **补丁与升级**：OS、k3s、containerd、Helm chart 定期升级；升级前备份（第 46 章）。
- [ ] **主机内核/运行时加固**：seccomp、AppArmor/SELinux（发行版支持情况不同）、sysctl 审计。

### 4.6 审计、检测与响应

- [ ] **Kubernetes Audit Log**：记录敏感资源访问，尤其 Secret、RBAC、exec、port-forward。
- [ ] **集中日志**：节点、k3s、审计、应用日志进入 Loki/ELK 等（第 49 章基础）。
- [ ] **监控告警**：API Server、etcd、节点资源、证书过期、Pod 重启、异常 webhook 拒绝（第 47 章）。
- [ ] **运行时检测**：Falco/Tetragon/eBPF 审计可检测异常 exec、敏感文件访问、容器逃逸行为。当前实验集群未安装。
- [ ] **Runbook**：每类告警有处理步骤、升级路径、回滚/逃生方案（第 36/43 章）。

### 4.7 备份与恢复

- [ ] **etcd snapshot**：定期、异地、加密、校验恢复（第 08/12/46/48 章）。
- [ ] **PV 备份**：local-path 不等于备份；有状态应用需应用级或存储级备份。
- [ ] **恢复演练**：备份没演练过等于没备份。至少季度演练恢复流程。
- [ ] **事故后复盘**：记录根因、影响面、修复、预防动作。

## 5. 建议优先级（从低成本高收益开始）

| 优先级 | 动作 | 成本 | 收益 |
|---|---|---|---|
| P0 | RBAC 审计、Secret 不入 Git、备份加密、管理端口限源 | 低 | 高 |
| P0 | 业务 namespace 默认 NetworkPolicy、PSA warn/audit | 中 | 高 |
| P1 | Audit Log、集中日志、告警规则完善 | 中 | 高 |
| P1 | 镜像扫描/固定 digest/私有仓库 | 中 | 中高 |
| P2 | 运行时安全（Falco/Tetragon）、签名验签准入 | 中高 | 中高 |
| P2 | CIS/kube-bench 自动化、合规基线报告 | 中 | 视合规要求 |

## 6. 本项目当前建议

结合本仓库现状，下一步最值得做的是：

1. **为教学 namespace 补 NetworkPolicy/PSA 标签模板**：低风险，能把 35/39 落地。
2. **补 etcd secrets encryption 与 audit log 教学章/实操**：属于 D 类安全空档。
3. **把 47/49/36 串成 Runbook 联动**：告警触发 → Dashboard → LogQL → 处理步骤。
4. **不要在当前双节点实验集群硬上 Falco/Harbor/Longhorn 全家桶**：资源不够，先文档化和轻量检查。

## 8. 小结

- 安全加固是分层工程：身份、密钥、工作负载、网络、节点、供应链、检测响应、恢复演练缺一不可。
- 本集群已有 RBAC、Kyverno、部分 NetworkPolicy、备份/监控/日志教学基础，但 PSA、审计日志、secrets encryption、运行时检测仍有缺口。
- 优先做低成本高收益项：最小权限、Secret 管理、备份恢复、NetworkPolicy、PSA、审计与告警联动。
